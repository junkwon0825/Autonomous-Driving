# Simulation Scenarios

Seven deterministic cases are implemented by `matlab/lkas_scenarios.m`. Every case is a new simulation design, not a recovered historical test. The complete result set is generated by `run_lkas_suite`.

| Case | Conditions |
|---|---|
| `straight_recovery` | Straight road, 10 m/s; initial lateral/heading error +0.02 m/+0.01 rad. |
| `constant_curve` | Constant curvature 0.003 1/m (333 m radius), 10 m/s; initial error +0.05 m/+0.02 rad. |
| `initial_offset` | Straight road, 10 m/s; initial lateral/heading error +0.15 m/+0.05 rad. |
| `speed_ramp` | Straight road, speed ramps linearly 7 to 15 m/s in 10 s; initial error +0.05 m/+0.02 rad. |
| `sensor_noise_and_disturbance` | +0.05 m/+0.02 rad initial error, deterministic lateral/heading measurement noise (0.01 m/0.003 rad amplitude) and 300 N sinusoidal lateral force. |
| `turn_signal_lane_change` | 10 m/s; turn signal from 2 to 7 s; smooth 3.5 m lateral reference transition from 3 to 7 s; return to lane-keeping mode afterward. |
| `sensor_noise_baseline` | Same initial conditions as the noisy case without measurement noise or lateral disturbance, for a paired comparison. |

The lane-change reference uses the quintic profile `10s^3 - 15s^4 + 6s^5` to start and end with zero lateral rate and acceleration. Its mode schedule is a new state-machine proposal, not the original Stateflow chart.

The noise signal is deterministic (a fixed combination of sinusoids), not a stochastic sensor model. The disturbance is a single lateral-force sinusoid. No camera latency, tire saturation, actuator lag, changing road friction, or random Monte Carlo cases are modeled.

Metrics are calculated from vehicle-state tracking errors. Settling time is the first sample after which absolute lateral error remains within 0.02 m. It is not reported for a lane-change transition or for a run that never settles. Overshoot is reported only when the initial lateral error is non-zero. These definitions are not verified against the historical presentation.
